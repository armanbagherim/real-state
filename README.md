# آشیان — مدیریت دفتر املاک

وب‌اپلیکیشن فارسی و راست‌به‌چپ برای فایل‌های فروش و اجاره، مالکین، قراردادها، پیگیری‌ها و یادآوری تمدید. رابط دسکتاپ دارای منوی کناری و جدول است؛ در موبایل فایل‌ها به‌صورت کارت و منو به‌صورت کشویی نمایش داده می‌شوند.

## اجرا

Node.js 22 LTS پیشنهاد می‌شود. PostgreSQL باید از محیط اجرای برنامه در دسترس باشد.

```sh
npm install
npm run db:generate
npm run dev
```

برنامه در `http://localhost:3000` اجرا می‌شود. تمام صفحات داخلی به ورود نیاز دارند. **نام کاربری و رمز مدیر ساخته‌شده فقط در `.env.local`، در کلیدهای `ADMIN_USERNAME` و `ADMIN_PASSWORD` قرار دارند.** Seed برای اجرای مجدد، رمز حساب موجود را تغییر نمی‌دهد.

برای نصب تازه، `.env.example` را به `.env.local` کپی و مقادیر را به‌صورت محلی تکمیل کنید:

| متغیر             | کاربرد                                               |
| ----------------- | ---------------------------------------------------- |
| `DATABASE_URL`    | آدرس اتصال PostgreSQL با تنظیم SSL مطابق سرویس‌دهنده |
| `NEXTAUTH_SECRET` | رشته تصادفی حداقل ۳۲ کاراکتری برای هش توکن نشست      |
| `NEXTAUTH_URL`    | آدرس اصلی برنامه؛ در استقرار عمومی باید HTTPS باشد   |
| `ADMIN_USERNAME`  | نام کاربری مدیر اولیه                                |
| `ADMIN_PASSWORD`  | رمز تصادفی اولیه با حداقل ۱۲ کاراکتر                 |
| `UPLOAD_DIR`      | محل نگهداری تصاویر؛ پیش‌فرض `./uploads`              |

نام دو متغیر `NEXTAUTH_*` برای سازگاری با درخواست اولیه حفظ شده است؛ احراز هویت این پروژه از نشست دیتابیسی اختصاصی استفاده می‌کند و وابسته به NextAuth نیست. متغیرهای حساس هرگز نباید با پیشوند `NEXT_PUBLIC_` تعریف شوند.

## دیتابیس و migration

```sh
npm run db:inspect
npm run db:migrate
npm run db:seed
```

`db:inspect` فقط اتصال و نام جدول‌ها را بررسی می‌کند. migration اولیه در `prisma/migrations` نسخه‌بندی شده و با `migrate deploy` اجرا می‌شود؛ این پروژه هیچ فرمان reset خودکاری ندارد. روی دیتابیس دارای داده، ابتدا schema، نسخه migration و نسخه پشتیبان را بررسی کنید؛ migration اولیه را روی جداول همنام ناشناخته اعمال نکنید.

Seed به‌صورت idempotent کاربر مدیر، تنظیمات و مالک نمونه ایجاد می‌کند. ملک‌های نمونه فقط زمانی اضافه می‌شوند که هیچ ملکی وجود نداشته باشد. شماره‌ها، مالک و ملک‌های نمونه برای آشنایی با برنامه‌اند و آگهی واقعی نیستند. قراردادهای نمونه و پیگیری‌ها نیز برای نمایش گردش کار ایجاد می‌شوند.

مدل‌ها: `User`, `Session`, `LoginAttempt`, `Owner`, `Property`, `PropertyImage`, `LeaseContract`, `FollowUp`, `Reminder`, `PropertyStatusHistory`, `Settings`.

کد فایل با sequence دیتابیس و تراکنش تولید می‌شود و در ثبت هم‌زمان یکتا می‌ماند. قیمت‌ها با `Decimal(18,0)` و تاریخ‌ها با `DateTime` ذخیره می‌شوند. نمایش و انتخاب تاریخ در رابط شمسی است؛ روز جاری بر مبنای منطقه زمانی تهران محاسبه می‌شود. مبلغ‌ها به تومان هستند.

## گردش کار

1. مالک را در `/owners/new` ثبت کنید.
2. فایل را در `/properties/new` بسازید و مالک را با جستجوی نام یا تلفن انتخاب کنید.
3. تصاویر را از صفحه جزئیات ملک اضافه کنید. ویرایش، تغییر وضعیت، آرشیو و حذف نرم از همان صفحه در دسترس‌اند.
4. قرارداد اجاره را در `/contracts/new` ثبت کنید. وضعیت ملک به اجاره‌رفته تغییر می‌کند و یادآوری‌های ۶۰، ۳۰، ۱۴ و ۷ روز قبل از پایان، با تنظیمات جاری دفتر ساخته می‌شوند.
5. برای تمدید، از دکمه «تمدید قرارداد» استفاده کنید. قرارداد قبلی حفظ و با وضعیت `RENEWED` ثبت می‌شود؛ یادآوری‌های باز قبلی بسته و یادآوری‌های قرارداد جدید ساخته می‌شوند. ثبت قرارداد فعال هم‌زمان برای یک ملک کنترل می‌شود.
6. در یادآوری‌ها، نتیجه تماس را ثبت کنید. «پاسخ نداد» و «تماس مجدد» یک پیگیری برای روز بعد می‌سازند. «تمدید قرارداد» فرم قرارداد واقعی را باز می‌کند.
7. در تنظیمات، نرخ تبدیل، روزهای یادآوری و اطلاعات دفتر را تغییر دهید. نرخ پیش‌فرض ۰٫۰۳ است. نرخ هنگام ثبت/ویرایش فایل در آن ذخیره می‌شود؛ تغییر تنظیمات، توافق قبلی فایل‌ها را بازنویسی نمی‌کند.

یادآوری‌ها **داخل برنامه** نمایش داده می‌شوند؛ ارسال پیامک، ایمیل یا Web Push در این نسخه پیاده‌سازی نشده است. کار زمان‌بندی‌شده خارجی برای نمایش یادآوری لازم نیست؛ سررسیدها با زمان فعلی مقایسه می‌شوند. تاریخ پایان‌گذشته در UI پایان‌یافته نمایش داده می‌شود؛ دکمه «پایان قرارداد» وضعیت ذخیره‌شده را نیز تغییر می‌دهد.

## ساختار

```text
src/app/              صفحات App Router و APIها
src/components/       رابط، فرم‌ها، جدول، تقویم شمسی و جستجوی انتخابی
src/components/ui/    اجزای shadcn-compatible بر پایه Radix و CVA
src/lib/              Prisma، احراز هویت، اعتبارسنجی و قالب‌بندی
src/repositories/     خواندن داده‌ها، صفحه‌بندی، فیلترها و کنترل دسترسی
src/services/         قواعد دامنه، تراکنش قرارداد/ملک، StorageProvider
src/actions/          عملیات محافظت‌شده و پیام‌های فرم
prisma/               schema، migration و seed
scripts/              بازرسی، تست یکپارچگی و تست مرورگر
tests/                تست‌های قواعد دامنه
public/               manifest assets، service worker و صفحه آفلاین
```

جستجو و فیلتر در سرور اجرا می‌شوند. لیست‌ها صفحه‌بندی دارند و انتخاب ملک/مالک از API محدود به ۲۰ نتیجه با debounce استفاده می‌کند؛ امکان جستجوی تمام رکوردها وجود دارد. فونت Vazirmatn از بسته محلی سرو می‌شود و به Google Fonts نیاز ندارد.

## امنیت و ذخیره تصویر

- رمزها با bcrypt و هزینه ۱۲ هش می‌شوند. توکن نشست تصادفی، به‌صورت HMAC در دیتابیس و کوکی `HttpOnly` و `SameSite=Lax` در مرورگر نگهداری می‌شود. کوکی در آدرس HTTPS، `Secure` است. نشست ۷ روز اعتبار دارد و هنگام خروج باطل می‌شود.
- کنترل ورود در لایه دریافت داده، تمام Server Actionها و APIهای خصوصی انجام می‌شود. ورود برای هر نام کاربری به ۱۰ تلاش در ۱۵ دقیقه محدود است.
- نقش `ADMIN` اجازه تغییر تنظیمات و حذف نرم فایل دارد؛ نقش `AGENT` عملیات معمول دفتر را انجام می‌دهد. حساب جدید از ثبت‌نام عمومی ساخته نمی‌شود.
- ورودی‌های فرم با Zod بررسی می‌شوند؛ کوئری‌ها پارامتری هستند. خطاهای اتصال، پیام قابل فهم در فرم/صفحه دارند.
- تصاویر JPG/PNG/WebP با حداکثر ۸ مگابایت پذیرفته، بازپردازش و به WebP تبدیل می‌شوند. فقط مسیر تصویر در PostgreSQL ذخیره می‌شود؛ خود فایل در `UPLOAD_DIR` است و دریافت آن نیاز به نشست معتبر دارد.
- `StorageProvider` در `src/services/storage.ts` نقطه جایگزینی دیسک با سرویس سازگار دیگر است. برای چند replica از فضای مشترک یا provider مشترک استفاده کنید.

## PWA

Manifest، آیکن‌های ۱۹۲ و ۵۱۲ پیکسل، آیکن maskable، حالت standalone و service worker آماده‌اند. در مرورگر پشتیبانی‌شده، گزینه نصب در منو ظاهر می‌شود؛ در iOS از Share → Add to Home Screen استفاده کنید. نصب عمومی نیاز به HTTPS دارد؛ localhost برای توسعه مجاز است.

داده‌های شخصی، APIها و تصاویر ملک در cache آفلاین ذخیره نمی‌شوند. هنگام قطع اینترنت صفحه راهنمای اتصال نمایش داده می‌شود؛ ثبت و مشاهده اطلاعات نیازمند اتصال است.

## بررسی‌ها

```sh
npm run typecheck
npm run lint
npm test
npm run test:integration
npm run build
```

تست یکپارچگی، fixtureهای موقت در دیتابیس فعلی ایجاد و در پایان فقط همان fixtureها را حذف می‌کند. روی استقرارهای بعدی بهتر است آن را با دیتابیس آزمایشی اجرا کنید. این تست اتصال مالک، ثبت هم‌زمان کدها، CRUD ملک، حذف نرم، قرارداد، جلوگیری از قرارداد تکراری، تمدید، یادآوری و تاریخچه وضعیت را بررسی می‌کند.

با سرور محلی روشن و Edge نصب‌شده:

```sh
npx tsx scripts/browser-check.ts
npm run test:flow
npx tsx scripts/pwa-check.ts
```

این تست اطلاعات ورود را فقط از `.env.local` می‌خواند؛ خروجی تصاویر در `.artifacts` قرار می‌گیرد و وارد Git نمی‌شود. صفحات محافظت‌شده، ورود، مسیرها، جستجو، Drawer موبایل و عرض ۳۷۵ پیکسل بررسی می‌شوند.

`test:flow` گردش واقعی ثبت و ویرایش مالک/ملک، آپلود تصویر، پیگیری و تمدید قرارداد را با داده‌های موقت بررسی و پاک‌سازی می‌کند. `pwa-check` فعال بودن service worker، صفحه آفلاین، نبود داده خصوصی در cache و نمایش افقی با reduced motion را بررسی می‌کند.

## استقرار و Docker

```sh
npm run db:migrate
npm run build
npm start
```

فرمان `npm start` خروجی standalone را همراه فایل‌های static و public آماده و اجرا می‌کند و مسیر تصاویر را به پوشه اصلی پروژه متصل نگه می‌دارد.

یا پس از تنظیم environment:

```sh
docker compose up --build -d
```

Dockerfile از خروجی standalone و کاربر غیر root استفاده می‌کند. `.env.local` وارد image نمی‌شود. migration و seed را پیش از استقرار و خارج از startup برنامه اجرا کنید؛ هیچ تغییری در دیتابیس با شروع container انجام نمی‌شود. Compose از PostgreSQL ابری استفاده می‌کند و volume مجزا برای تصاویر دارد. HTTPS را در reverse proxy فعال و `NEXTAUTH_URL` را مطابق دامنه واقعی تنظیم کنید. حجم بدنه درخواست آپلود را در proxy نیز به ۹ مگابایت محدود کنید.

برای پشتیبان‌گیری، از `pg_dump` استاندارد PostgreSQL و پشتیبان مجزای `UPLOAD_DIR`/volume استفاده کنید. اعتبارنامه را از فایل امن یا `.pgpass` بخوانید؛ در خط فرمان عمومی یا لاگ ثبت نکنید. بازیابی را در محیط جدا آزمایش کنید. تغییر میزبان PostgreSQL فقط به اصلاح `DATABASE_URL` نیاز دارد.

منابع: [راهنمای Next.js](https://nextjs.org/docs/app/getting-started/installation)، [Prisma Migrate برای production](https://www.prisma.io/docs/orm/v6/prisma-client/deployment/deploy-database-changes-with-prisma-migrate).
